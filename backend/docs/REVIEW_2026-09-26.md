# ผลตรวจเพิ่มเติม — 26 กันยายน 2569

สถานะ 27 กันยายน 2569: แก้ทั้ง 8 จุดด้านล่างแล้ว พร้อมแก้การโหลดต้นฉบับซ้ำ, token สำหรับลองนำเข้าใหม่, ย้ายการอ่านและจำแนกต้นฉบับออกจาก transaction, ref ระหว่าง render และ type contract ของหน้านำเข้า รายละเอียดด้านล่างเก็บเป็นหลักฐานอาการก่อนแก้ เลขบรรทัดอ้างอิงโค้ด ณ วันที่ตรวจ ดูผลทดสอบล่าสุดใน [CHANGE_AUDIT.md](CHANGE_AUDIT.md)

ตรวจโค้ดปัจจุบันและทำซ้ำด้วยข้อมูลจำลอง พบเพิ่ม 8 จุดนอกเหนือจาก 5 ข้อที่ตรวจไปก่อนหน้า ไม่ได้แก้โค้ดระบบหรือข้อมูลทะเบียนจริง ผลนี้ยืนยันเส้นทางที่เกิดปัญหาได้ ไม่ได้หมายความว่าข้อมูลจริงเสียหายแล้ว

1. **[P1] ราคาที่มี comma คำนวณยอดรวมผิด**

   จุดเกิด: [editor.tsx:245](../../frontend/features/inventory/editor.tsx#L245), [domain.ts:10](../contracts/domain.ts#L10), [asset-mutations.ts:78](../services/asset-mutations.ts#L78)

   จำนวน 2 หน่วย กรอกราคาต่อหน่วย `1,000.00` ทำให้ `parseFloat()` คำนวณยอดรวมเป็น `2.00` บาท แต่ตอนบันทึก `satang()` อ่านราคาต่อหน่วยเป็น 1,000 บาทถูกต้อง หากมีข้อความเหตุผล Backend ยอมรับยอดรวมที่ไม่ตรงสูตร จึงบันทึกยอดรวม 2 บาทได้ ทั้งการเปลี่ยนราคาและเปลี่ยนจำนวนใช้วิธีแปลงนี้ ควรใช้ตัวแปลงเงินเดียวกันและคำนวณด้วยจำนวนสตางค์

   หลักฐาน: รัน body ของ `handlePriceChange` ที่ดึงจากไฟล์จริงกับตัวแปลง `satang()` จริง ได้ราคาหน่วย 100,000 สตางค์ แต่ยอดรวม 200 สตางค์

2. **[P1] ข้อความหมายเหตุทำให้แถวครุภัณฑ์ถูกตัดออกจากรายการนำเข้า**

   จุดเกิด: [domain.ts:79](../contracts/domain.ts#L79), [asset-service.ts:96](../services/asset-service.ts#L96)

   แถวที่รหัส ชื่อ จำนวน และราคาครบ แต่หมายเหตุเป็น `เจ้าหน้าที่พัสดุ` ถูกจัดเป็นหัวตาราง เพราะข้อความรวมทุกคอลัมน์ตรงกับ `/หน้าที่/` ก่อนตรวจว่าเป็นครุภัณฑ์ ส่วน `ซื้อรวมเป็นเงิน 10000 บาท` ถูกจัดเป็นยอดรวม แถวดังกล่าวจึงไม่อยู่ในรายการรอนำเข้าหรือตรวจทาน และนำเข้าแบบกลุ่มไม่ได้ ต้นฉบับยังอยู่ แต่รายการที่ควรเข้าทะเบียนถูกซ่อนจากขั้นตอนปกติ ควรจำแนกหัวตาราง/ยอดรวมตามโครงสร้างแถวและคอลัมน์

   หลักฐาน: เรียก `classify()` จริงด้วยแถวเดียวกัน เปลี่ยนเฉพาะหมายเหตุ: `ผู้ดูแลพัสดุ` → asset, `เจ้าหน้าที่พัสดุ` → header, `ซื้อรวมเป็นเงิน 10000 บาท` → subtotal

4. **[P2] ครุภัณฑ์มูลค่า 0 บาทแก้รายละเอียดไม่ได้**

   จุดเกิด: [editor.tsx:210](../../frontend/features/inventory/editor.tsx#L210), [editor.tsx:280](../../frontend/features/inventory/editor.tsx#L280), [editor.tsx:667](../../frontend/features/inventory/editor.tsx#L667)

   ฟอร์มเปลี่ยนราคา 0 เป็นข้อความว่าง จากนั้นช่องราคาขณะ edit เป็น readOnly ผู้ใช้แก้กลับไม่ได้ เมื่อบันทึกชื่อ/หมายเหตุ `satang('')` จะปฏิเสธ แม้ Backend อนุญาตราคา 0 รวมถึงรายการลูกหลังแบ่งยอด ควรแสดงค่า 0 เป็น `0.00` และแยกจากข้อมูลที่ไม่ได้ระบุ

   หลักฐาน: `validated()` จริงยอมรับรายการราคา 0 แต่ expression ตั้งค่าฟอร์มจากไฟล์จริงคืนข้อความว่าง และ `satang()` จริงโยน error

5. **[P2] แนบรูปตอนสร้างรายการแล้วอัปโหลดล้มเหลวโดยไม่มีข้อความแจ้ง**

   จุดเกิด: [editor.tsx:297](../../frontend/features/inventory/editor.tsx#L297), [workspace.tsx:67](../../frontend/features/inventory/workspace.tsx#L67)

   บันทึกครุภัณฑ์แล้วฟอร์มปิดและแจ้งสำเร็จก่อนส่งรูป หาก API รูปตอบ 400/413/500 โค้ดละทิ้งผลนั้น; network error ถูกเขียนเฉพาะ console ผู้ใช้จึงไม่ทราบว่ารายการมีแล้วแต่รูปไม่สำเร็จ เช่น รูปเสียหรือเกิน 25 ล้านพิกเซล ควรแจ้งผลสองส่วนให้ชัดและมีทางลองอัปโหลดรูปอีกครั้งโดยไม่สร้างครุภัณฑ์ซ้ำ

   หลักฐาน: รันบล็อกส่งรูปจากไฟล์จริงกับ HTTP 400 จำลอง handler จบตามปกติ ไม่มีการแจ้ง error หรือเรียก refresh รูป

6. **[P2] ฟอร์มตรวจนับเก่าเขียนทับผลใหม่ได้**

   จุดเกิด: [asset-mutations.ts:246](../services/asset-mutations.ts#L246), [editor.tsx:334](../../frontend/features/inventory/editor.tsx#L334)

   เจ้าหน้าที่ A และ B เปิดรายการเดียวกัน A บันทึกไม่พบ/0 แล้ว B ส่งฟอร์มเก่าว่าปกติ/2 ภายหลัง ระบบยอมรับทั้งคู่ เพราะไม่มี expected version หรือค่า checkedAt เดิมให้เปรียบเทียบ ผลปัจจุบันถูกทับแม้ค่าเก่ายังอยู่ใน audit ควรตรวจความสดของรายการก่อนบันทึกแล้วให้ผู้ใช้ทบทวนเมื่อข้อมูลเปลี่ยน

   หลักฐาน: รัน `mutate()` จริงกับ Prisma จำลองในหน่วยความจำ ทั้งสองคำขอคืน ok และผลสุดท้ายเป็นของ B

   จุดเกิด: [asset-mutations.ts:249](../services/asset-mutations.ts#L249), [editor.tsx:988](../../frontend/features/inventory/editor.tsx#L988)

   หลักฐาน: `mutate()` จริงกับข้อมูลจำลอง snapshot=2, result=mismatch, quantity=3 คืน ApiError 400
