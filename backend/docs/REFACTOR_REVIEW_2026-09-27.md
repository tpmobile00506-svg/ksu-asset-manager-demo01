# ตรวจการแยกคอมโพเนนต์ — 27 กันยายน 2569

ตรวจโค้ดหลัง Antigravity แยก Editor และ Operations: โครงสร้างแยกตามหน้าที่จริง แต่การย้ายฟอร์มเปลี่ยนพฤติกรรมบางส่วน ผล typecheck และ unit tests เดิม 25/25 ผ่านก่อนแก้ ไม่ครอบคลุมข้อผิดพลาดต่อไปนี้

## สถานะหลังแก้ — 27 กันยายน 2569

แก้ทั้ง 5 จุดแล้ว: ฟอร์มรักษาสาขาเดิมและรับสาขาที่พิมพ์เพิ่ม, ส่งสภาพที่เลือกจริง, ใช้ id ที่ Backend คืนเพื่อแนบรูปหลังนำเข้า, คืน readOnly ให้จำนวนและเงินในโหมดแก้ไข และไม่แสดงหรือพิมพ์ QR จากชุดก่อนเมื่อเปลี่ยนรายการหรือปิดหน้าต่าง ปุ่ม QR ในทะเบียนปิดเมื่อไม่มีรายการที่มีสิทธิ์สร้างป้าย

เพิ่มสัญญาข้อมูลร่วมใน `backend/contracts/models.ts` ให้ Backend ตรวจรูปแบบผลตอบกลับระหว่าง compile และให้ views ใช้ props ตามสัญญาเดียวกัน แก้ชื่อ `roundId`, ชนิด `active` เป็นจำนวน และเพิ่ม `version` ของคำขอ ส่วนข้อค้นพบด้านล่างเก็บเป็นหลักฐานก่อนแก้

## ข้อผิดพลาดที่ยืนยันก่อนแก้

1. **P1 — สาขาเดิมถูกแทนด้วยตัวเลือกแรกในฟอร์ม** (`asset-form-modal.tsx`)
   - ตัวเลือกสาขาตายตัวไม่รวมค่าจากทะเบียนหรือต้นฉบับ
   - ยืนยันใน browser: ทะเบียนสาขา `ทดสอบ` เปิดแก้ไขแล้วแสดง `สำนักงานคณบดี (ควอ.)` โดยผู้ใช้ยังไม่ได้เปลี่ยนสาขา หากบันทึกชื่อ/หมายเหตุพร้อมเหตุผล ค่าสาขาที่ผิดจะถูกส่งไปด้วย
   - ต้องรักษาค่าเดิมและรองรับค่าจากข้อมูลจริง รวมถึงการกรอกสาขาเพิ่มเติม

2. **P2 — เปลี่ยนสภาพครุภัณฑ์ไม่ได้** (`asset-form-modal.tsx`)
   - ส่ง `value` ให้ Pick โดยไม่มี `onChange`
   - ยืนยันใน browser: เลือก `ชำรุด` แล้วฟอร์มยังแสดง `ปกติ`
   - ต้องใช้ state พร้อม setter หรือ defaultValue ให้ฟอร์มส่งค่าที่เลือกจริง โดยคงกฎคำขอซ่อมของ Backend

3. **P2 — รูปที่แนบตอนนำเข้าทีละรายการไม่ถูกอัปโหลด** (`asset-form-modal.tsx`)
   - ฟอร์ม import แสดงช่องรูป แต่เลือก id จาก response เฉพาะ create; Candidate จากต้นฉบับยังไม่มี id
   - ทดสอบ submit ของคอมโพเนนต์ด้วยข้อมูลจำลอง: Backend คืน id แล้ว แต่ไม่มีคำขออัปโหลดรูป
   - ต้องใช้ id ที่ Backend คืนหลังนำเข้าสำเร็จ และรักษาการแจ้ง partial failure โดยไม่สร้างรายการซ้ำ

4. **P2 — ฟอร์มแก้ไขเปิดช่องจำนวนและเงินที่บันทึกไม่ได้** (`asset-form-modal.tsx`)
   - readOnly ในโหมด edit หายไป แต่ Backend ยังคงปฏิเสธการเปลี่ยนจำนวน ราคาหน่วย และยอดรวมของทะเบียน
   - ต้องคืนข้อจำกัดในฟอร์มและชี้ไปยังงานแบ่งล็อต

5. **P2 — ป้าย QR ค้างจากชุดก่อนเมื่อชุดใหม่ไม่มีรายการที่ถือครอง** (`qr-label-modal.tsx`, `workspace.tsx`)
   - เปิด QR รายการ active แล้วปิด จากนั้นกรองทะเบียนจำหน่ายแล้วและกด QR; ชุดที่ส่งให้ modal เป็น [] แต่ effect ข้ามการล้างป้ายเดิม
   - ยืนยันใน browser: ตารางแสดงรายการจำหน่าย `AIR-…` แต่ modal กลับแสดง `UI-ZERO-20260927` และปุ่มพิมพ์ยังใช้ได้
   - ต้องล้างป้ายเก่าและปิดปุ่มเปิด/พิมพ์เมื่อไม่มีรายการที่มีสิทธิ์สร้างป้าย

## ข้อจำกัดของรายงาน Type Safety

ก่อนแก้ models มีชื่อ/ชนิดไม่ตรงข้อมูลจริงและหลาย view รับ Any ซึ่งแก้ด้วยสัญญาข้อมูลร่วมแล้ว อย่างไรก็ตาม `api<T>()` ยังลงท้ายด้วย type assertion หลังตรวจโครงสร้างเบื้องต้น จึงไม่ได้ตรวจทุก field ให้ครบตาม T ข้อมูล JSON ที่เก็บเป็น string เช่น payload, chain, snapshot และ audit before/after ยังไม่ได้ตรวจโครงสร้างภายในทั้งหมดตอน runtime การผ่าน typecheck ไม่ทดแทน runtime validation และไม่ได้หมายความว่าเลิกใช้ Any ทั้งโปรเจคแล้ว
